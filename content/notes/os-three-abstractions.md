# 操作系统的三个抽象

操作系统做了很多事，但真正暴露给应用程序的，主要是三个抽象：

1. **进程**：一个正在执行的程序。
2. **地址空间**：进程独占的一片内存。
3. **文件**：可以持久保存的字节序列。

把这三个东西想清楚，很多系统问题就有了统一的解释。

## 进程：CPU 的抽象

物理机器上只有有限个 CPU 核心，但我们可以同时运行几百个程序。操作系统给每个程序一个幻觉：**你独占了一台 CPU**。

这个幻觉由三样东西维持：

- **上下文切换**：保存寄存器、切换栈、换页表。
- **调度**：决定下一个运行谁。公平、优先级、实时性，都是在这层做的取舍。
- **状态机**：运行、就绪、阻塞。进程的大部分时间其实不在运行，而在等 I/O。

衡量调度器时，最常用的三个量是：

$$
T_{\text{turnaround}} = T_{\text{completion}} - T_{\text{arrival}}, \qquad
T_{\text{response}} = T_{\text{first run}} - T_{\text{arrival}}
$$

其中 $T_{\text{turnaround}}$ 关心“多久做完”，$T_{\text{response}}$ 关心“多久有反应”。交互式系统更在意后者，批处理系统更在意前者。

一个最小的进程实验：

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();
    if (pid == 0) {
        execlp("echo", "echo", "child", NULL);
        _exit(127);
    }
    int status;
    waitpid(pid, &status, 0);
    printf("child exited with %d\n", WEXITSTATUS(status));
    return 0;
}
```

`fork` 复制地址空间，`exec` 替换程序映像，`wait` 回收状态。三个系统调用，构成了 UNIX 进程模型的基本操作。

## 地址空间：内存的抽象

每个进程都以为自己拥有一整片连续内存，从地址 0 开始。实际上，虚拟地址到物理地址的映射由页表维护，操作系统和 MMU 一起完成翻译。

这层抽象带来三个好处：

1. **隔离**：一个进程不能随意读写另一个进程的内存。
2. **简化**：程序不需要关心物理内存碎片，链接器可以假设固定的地址布局。
3. **按需分配**：页面可以延迟加载、换出、共享。

代价是每次内存访问都要经过地址翻译。TLB 缓存了最近的映射，才让这件事变得可接受。

一个常见的误解是“内存越大程序越快”。真正影响性能的往往是**访问模式**：顺序访问比随机访问快，局部性好比容量大更重要。

## 文件：持久化的抽象

内存断电就没了。文件系统把块设备包装成目录树和字节流，让程序可以用 `open / read / write / close` 操作持久数据。

UNIX 的设计里，“一切皆文件”不只是口号：

- 终端是文件（`/dev/tty`）。
- 管道是文件（`pipe()` 返回两个 fd）。
- 套接字可以是文件（`socket()` 返回 fd）。
- 设备是文件（`/dev/sda`）。

统一的 `read/write` 接口让程序可以用同一套代码处理键盘、磁盘和网络。代价是有些设备的语义并不能完美映射到字节流，于是又有了 `ioctl` 这样的逃生舱。

文件系统真正难的地方不是“怎么存”，而是“怎么在崩溃后仍然一致”。日志（journaling）、写时复制（CoW）、fsync 的顺序，都是围绕这个问题展开的。

## 三者如何组合

一个 shell 管道：

```bash
grep error app.log | sort | uniq -c | head
```

这里同时用到了三个抽象：

- 四个**进程**并发执行，由调度器切换。
- 每个进程有自己的**地址空间**，管道缓冲区在内核里传递数据。
- `app.log` 是**文件**，标准输入输出也被抽象成文件描述符。

再看容器：它没有发明新的抽象，只是把已有的东西组合起来——`namespaces` 隔离进程看到的视图，`cgroups` 限制资源，`rootfs` 提供文件系统。所谓“容器”，本质上是一个被限制了视野的普通进程。

## 一个思考框架

遇到一个新的系统机制时，可以问三个问题：

1. 它给应用程序提供了什么**幻觉**？
2. 维持这个幻觉需要付出什么**代价**？
3. 幻觉被打破时，**错误**如何暴露给上层？

用这个框架看虚拟内存、写时复制、异步 I/O、分布式文件系统，会发现它们都在回答同一类问题。

操作系统不难在概念，难在把概念和真实的代码、真实的性能数字对上。多写几个小实验，比读十遍教材有用。
