## 项目 1：[推理性能剖析](project-serving-benchmark.md)

**一句话**：用 vLLM 部署一个 7–8B 模型，把"batch × 序列长度 → 吞吐/延迟"的曲线画出来，并用 Roofline 解释每一段的形状。

- **难度**：★★☆☆☆
- **最低硬件**：单张 ≥ 16GB 显存的 GPU（7B 模型 bf16 权重约 14GB）
- **技术栈**：vLLM + Python + matplotlib
- **最核心的一点**：**不是测出数字，而是解释数字**。曲线形状和理论预测对不上，才是最有价值的发现。

## 项目 2：[Mini Serving 引擎](project-mini-serving.md)

**一句话**：用 PyTorch 手写一个简化版 serving 引擎（静态 batching + 预分配 KV cache），对比 HuggingFace `generate` 的吞吐。

- **难度**：★★★★☆
- **最低硬件**：单张 ≥ 8GB 显存的 GPU（用 1.5B 模型即可做）
- **技术栈**：PyTorch + KV cache 管理 + 一个简单 HTTP 服务（FastAPI）
- **最核心的一点**：亲手管一次 KV cache，你才真正读懂了 PagedAttention。

## 项目 3：[训练加速对比](project-train-parallel.md)

**一句话**：用 DDP 和 FSDP 训练同一个模型，测量吞吐、显存、通信开销，并与 ZeRO 论文的理论做对照解释。

- **难度**：★★★☆☆
- **最低硬件**：**2 张以上同型号 GPU**（只有单卡就跳过本项目，或用云 GPU）
- **技术栈**：PyTorch FSDP / DDP + `torch.profiler`
- **最核心的一点**：解释"为什么实测加速比低于线性"——通信、同步、激活重算。

## 所有项目通用的验收标准

一个 AI Infra 项目"算做完了"，需要以下 **5 件事全有**：

- [ ] 1. **可复现的脚本**：别人 checkout 后一条命令能重跑你的实验
- [ ] 2. **原始数据**：csv/json 里的每次测量结果（不要只交图）
- [ ] 3. **一张对比图**：横纵轴、单位、图例齐全
- [ ] 4. **理论 vs 实测的对照**：用第 1 周的工具算出理论值，解释差距来源
- [ ] 5. **"我学到的最反直觉的一件事"**：一句话
